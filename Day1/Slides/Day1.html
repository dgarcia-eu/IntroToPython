Course aims

After this course, you should:

  • Have a solid foundation in Python programming.

  • Understand fundamental programming concepts such as variables, control flow, basic data structures, and functions,

  • Know how to load, manipulate, and visualize data in Python

  • Be able to apply these skills to basic data analysis and programming in other courses and to start developing more advanced, domain-specific Python skills.

Target audience

This course is designed for first-semester students of Social and Economic Data Science

  • Who has ever written a simple script?
  • Who has learned programming before?
  • In which languages?
  • The target audience is students with nearly zero programming experience. There will be extra ungraded exercises for those of you with more experience.

Teaching approach

  • Mornings: Interactive lectures that cover theoretical and technical aspects of programming with Python
    • Mostly based on going together through notebooks with concepts and exercises
    • It is essential that you have the notebook in front of you and that you try the coding exercises

  • Afternoons: Practical tutorials where you apply the acquired knowledge in assignments

Using AI to write code

Vibe coding: using a chatbot to write your code and running it without understanding it.

Fine for a hobbyist. Not fine for a data scientist: you are responsible for the code you run and the results you publish.

You cannot defend a finding you cannot explain, and you cannot debug code you did not read.

The rule in this course

Do not copy code you do not understand. From a chatbot, from Stackoverflow, from another student — the source does not matter, the understanding does.

  • The assignments are how you find out whether you can do this yet. Outsourcing them tells you nothing.
  • The exam is on paper, closed book, and there is no chatbot in it.
  • Autocomplete plugins are fine — as long as you read what they suggest and would have written it yourself.

What to use it for instead

  • “Explain this error message to me” — genuinely useful, and it teaches you something reusable.
  • “What does this line do?” on code you already have.
  • “Give me three more exercises like this one.”
  • “I think X, am I wrong?” — argue with it, don’t dictate to it.

Ask it to explain, not to produce. The moment you paste code you cannot read, you have stopped learning and started gambling.

Chatbots are confidently wrong

On Day 4 you will be given a piece of plausible-looking, chatbot-flavoured code with two bugs in it, and asked to find them.

  • It looks right. It runs. It gives a wrong answer.
  • No error message will tell you.
  • The only defence is being able to read it and judge whether the result is plausible.

That is the skill this course is actually for.
